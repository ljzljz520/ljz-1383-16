# 证书奖项证据管理架构

## 1. 目标与边界

构建“证书/奖项身份 + 生命周期事件 + 公开/私密证据文件 + 下游传播”的证据管理系统。访客墙只展示文字事实、已核对来源状态和脱敏派生图；管理 API 允许站主录入签发方、有效期、成长目标、事件和证据文件。

必须明确区分以下概念：

- **证书身份**：同一张证书或同一个奖项的稳定主体，例如签发方 + 个人编号 + 证书类型。
- **生命周期事件**：新获奖、补发图片、续期、撤销、签发机构更名、链接检查等。
- **证据文件版本**：原件、OCR/元数据提取结果、脱敏派生图、处理失败记录。
- **读取状态**：有效期、撤销状态、来源核对状态、图片状态，是读取时或读模型中的派生结果，不是站主主观声明。

链接仍可访问只代表“该 URL 当时可到达/返回内容”，**不能自动推出证书真实、有效或被权威认证**。只有签发方权威记录中的关键字段匹配，才可标记为“已核对来源”；即便如此，页面也应说明核对时间与范围。

## 2. 领域模型

### 2.1 证书身份

证书身份使用稳定 `certificate_id`，并对以下规范化字段建立唯一键：

```text
issuer_id + credential_type + normalized_credential_number
```

- 签发方更名不改变身份，通过签发方名称历史表记录。
- 编号可能有新版式：保留原始编号文本、规范化编号、显示编号（脱敏）。
- 没有编号的奖项使用可审计的替代键：签发方、奖项名称、获奖日期、获奖名单位置、站主主体标识的强匹配组合；匹配不足时只能保持“自报材料”。
- 同一张证书补发、换发图片、续期不新建身份，也不增加成就数量。
- 新获奖或另一独立奖项才创建新身份；无法确定是否同一身份时进入人工复核，不自动新增成就。

### 2.2 事件类型

事件表只追加，不物理覆盖：

| 事件 | 是否新成就 | 说明 |
|---|---:|---|
| `award.created` | 是 | 首次获奖或取得证书；每个身份最多一条有效获奖事件 |
| `certificate.renewed` | 否 | 新有效期或续期区间，链接到原身份 |
| `certificate.reissued` | 否 | 证书实体补发，可包含新编号映射，但不改变身份 |
| `asset.uploaded` | 否 | 上传私密原件或补充文件 |
| `asset.replaced` | 否 | 替换图片版本，旧版本仍保留 |
| `asset.derivation_failed` | 否 | 脱敏派生失败，不影响已录入身份，但公开图为空 |
| `certificate.revoked` | 否 | 撤销；可带追溯生效时间 |
| `certificate.reinstated` | 否 | 撤销被取消或证书恢复 |
| `issuer.renamed` | 否 | 签发机构更名，身份与历史记录不断裂 |
| `verification.checked` | 否 | 一次来源核对尝试或结果，不等同新证书 |
| `verification.link_broken` | 否 | 验证链接失效，不自动撤销证书 |

事件保存两个时间：

- `effective_at`：业务上生效的时间，用于午夜到期、续期、追溯撤销。
- `recorded_at`：服务器实际接收事件的时间，用于审计、延迟入库和时钟校正。

## 3. 状态计算：实时计算与事件驱动更新

采用**权威实时归约 + 事件驱动读模型缓存**的混合方案。

### 3.1 写入侧：实时归约是权威口径

状态函数以证书身份的事件流为输入：

```text
state(events, now) =
  1. 按 effective_at 排序，同一时刻按 event_sequence 排序
  2. 找到 now 所属的有效区间
  3. 若 now >= 最近的追溯撤销点且之后没有恢复，则 REVOKED
  4. 若 now < awarded_at，则 NOT_ACTIVE
  5. 若当前有效区间 expires_at <= now，则 EXPIRED
  6. 否则 VALID
```

补充规则：

- 只存“日期”的有效期必须连同签发方时区和业务口径保存；若签发方规定为到期日 23:59:59，则在该时区显式转换为该时刻，不能使用服务器本地午夜。
- 示例：`2026-10-07 00:00 Asia/Shanghai` 到期，表示上海时间午夜即失效；UTC 客户端不能提前/延后显示。
- 追溯撤销按 `effective_at` 归位，迟到事件到达后重新归约受影响区间。
- 已撤销后的迟到续期不能让证书复活；除非存在恢复事件或人工裁决事件。
- 冲突裁决写入决策事件，保留两条输入事件和幂等处理结果。

### 3.2 读取侧：事件驱动更新用于传播和性能

后台维护 `certificate_read_models`、技能证据链接和简历候选投影：

1. 管理 API 在一个数据库事务中写业务事件和 `outbox`。
2. Outbox worker 更新缓存读模型、技能证据索引和简历候选。
3. 到期 worker 不制造业务事实，只在越过到期点时刷新读模型/通知；权威状态仍由时间比较得到。
4. 读模型必须带 `state_computed_at`、事件流版本和时钟来源；访客 API 可在响应时用当前权威时间快速校正临界状态。

两种方式对比：

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 每次读取实时归约 | 口径强一致，不怕 worker 漏跑 | 高并发下成本高，难以下游聚合 | 管理详情、争议处理使用 |
| 纯事件驱动缓存 | 查询快，便于传播 | 服务器时钟跳变、迟到撤销可能造成短暂错误 | 不单独作为权威口径 |
| 混合方案 | 权威可重算，公开页快，到期可调度 | 需要版本和补偿任务 | 推荐 |

## 4. 时钟校正与午夜到期

- 所有时间以 UTC `timestamptz` 存储，同时保留 `expires_local_date`、`expires_at_timezone` 和签发方口径。
- 调度器使用单调时钟计算“下一次触发还剩多久”，墙钟只用于生成业务时间。
- NTP 调整后重新加载未来 24 小时的到期任务；重复触发通过证书 ID + 到期区间幂等。
- `recorded_at` 不因时钟回拨而修改；若发现写入时曾使用错误时钟，新增 `clock.correction_recorded` 审计事件并标记受影响投影重建。
- 对临界证书（例如到期前后 5 分钟）公开 API 读取时重新比较当前权威时间。
- 服务器定期从可信时间源获取 `authoritative_now`，不信任客户端时间；静态演示页的浏览器时间只用于界面演示。

## 5. 并发：续期与撤回同时发生

管理 API 使用每个证书身份的串行化写入或数据库行锁：

```sql
BEGIN;
SELECT * FROM certificates WHERE certificate_id = $1 FOR UPDATE;

-- 校验事件流版本 version = expected_version
-- 校验幂等键 request_id / idempotency_key 不存在
-- 分别写入 renewed 与 revoked 事件，不因为“先来后到”丢弃另一条
-- 按 effective_at + event_sequence 归约
-- 若撤销点覆盖续期区间，当前状态为 revoked，但续期历史仍保留

COMMIT;
```

验收并发场景：

1. 两个请求都携带唯一 `Idempotency-Key`。
2. 同一请求重试不得产生两条事件。
3. 续期成功与撤回成功同时提交时，两者都在事件链可见。
4. 若撤销 `effective_at` 早于续期开始，当前为 `REVOKED`；续期作为被覆盖区间保留。
5. 下游只传播最终状态：撤销会移出现行技能证据和简历候选，但冻结简历快照不覆盖。
6. 冲突无法自动裁决时返回 `409`，进入管理后台复核队列，不猜测优先级。

## 6. 图片、个人编号与元数据：公开/私密分离

### 6.1 处理流水线

1. 管理端上传到**私密原件桶**，默认私有 ACL，服务端校验 MIME、魔数、大小和病毒扫描。
2. 创建 `asset.uploaded` 事件，状态为 `processing`。
3. OCR/EXIF/PDF 元数据识别个人编号、姓名、签发日期、有效期、签发方、证书类型。
4. 识别结果中的敏感字段加密入库，只保存不可逆哈希用于去重与匹配。
5. 生成公开派生图：遮蔽编号、证件号、地址、二维码、可识别照片/签名；需要时重绘为摘要图。
6. 派生图进入公开桶，写入 `asset.derived`；处理成功前公开页不得回退展示原件。
7. 处理失败写入 `asset.derivation_failed` 和错误原因，公开页显示“图片处理失败，仅展示文字证据”，并允许后台重试。

### 6.2 访问控制

- 私密原件 URL 永远不出现在公开 API/HTML。
- 管理端访问原件使用短期签名 URL，并记录审计日志。
- 公开桶只允许访问显式标记 `is_public_current` 的派生图。
- 删除公开图不会删除原件；替换派生图保留旧版本和修订原因。
- EXIF 中的 GPS、设备序列号等默认剥离。
- 编号展示采用分段脱敏，例如 `NO.****-****-1234`；完整编号只在授权管理界面显示。

## 7. 来源核对与链接状态

来源状态至少分为：

1. **自报材料**：只有站主上传文件或手工录入，未完成签发方核对。
2. **链接可访问**：URL 可达，但未证明页面内容属于该证书；不得使用“已认证”。
3. **已核对来源**：权威签发方记录中的脱敏编号、主体标识、证书类型、有效期等关键字段匹配；记录核对时间、字段范围、抓取证据快照（可为私密）。
4. **链接失效/来源陈旧**：超时、404、TLS 错误、页面删除；不自动撤销，只降低来源在线可用性。
5. **签发方矛盾/撤销**：签发方明确显示无效、撤销或主体/编号不一致；进入矛盾或撤销状态。

HTTP 200 只能作为可访问信号。证书真实性核对必须有独立的字段匹配结果，例如：

```json
{
  "result": "verified",
  "matched_fields": ["credential_number_hash", "subject_hash", "credential_type", "validity_range"],
  "checked_at": "2026-09-30T08:45:00Z",
  "scope": "issuer_registry"
}
```

## 8. 下游传播：技能证据与简历

- 技能证据引用的是证书身份和当前可公开状态，不复制不可变事实。
- 状态变为有效/已核对时，可以加入候选技能证据。
- 状态变为过期、撤销、来源矛盾时，从“当前可用证据”移除；历史时间线仍可保留。
- 简历草稿或候选列表随投影更新。
- 简历一旦冻结（例如已导出、已投递、候选人确认），其快照不可覆盖。冻结版本仍可追加“生成后撤销/过期”的警示，但不能改写当时的快照文本。

传播采用 outbox，消费者以 `event_id` 幂等；迟到撤销触发补偿任务，重新计算未来简历候选和技能聚合，但冻结简历不变。

## 9. 访客墙展示规则

页面状态必须分开表达，不把多个维度混成一个“真/假”：

- 有效期：当前有效 / 未生效 / 已过期 / 已撤销。
- 来源：自报材料 / 链接可访问 / 已核对来源 / 链接失效 / 签发方撤销或矛盾。
- 图片：公开脱敏图 / 图片处理失败 / 历史撤销标记图。
- 时间：展示到期本地时间和 IANA 时区，例如 `Asia/Shanghai`。
- 事件链：折叠展示新获奖、补发、续期、更名、撤销、来源核对。
- 排序：允许最近事件、到期时间、标题等事实排序；不提供也不生成“含金量”“权威等级”之类无来源评分。

建议文案：

- “自报材料：尚未完成签发方记录核对。”
- “已核对来源：YYYY-MM-DD 与签发方记录的脱敏编号及有效期匹配。”
- “验证链接当前不可达；这不自动代表证书被撤销。”
- “已撤销：签发方复审不通过，撤销效力追溯至 YYYY-MM-DD。”
- “已过期：仅作为历史证据，不作为当前有效证书。”

## 10. 管理 API 原则

- 仅站主/管理员可访问，使用短期访问令牌、刷新令牌轮换、审计日志和最小权限。
- 写接口接收 `Idempotency-Key`、期望事件流版本和变更原因。
- 管理 API 返回的编号默认脱敏；查看完整编号需要额外权限和二次确认。
- 上传与元数据录入分离：图片处理失败不得阻止证书身份事实录入，但不得公开原件。
- 机构更名更新当前显示名并保留名称历史，旧简历仍显示当时名称。

接口契约见 [`api-contract.md`](./api-contract.md)，数据库结构见 [`../db/migrations/001_certificate_evidence.sql`](../db/migrations/001_certificate_evidence.sql)。

## 11. 验收用例

| 场景 | 预期 |
|---|---|
| 同一证书第二次上传图片 | 只新增文件版本，不新增证书身份或成就 |
| 同一证书续期 | 新增续期事件和有效期区间，成就计数保持 1 |
| 新获奖 | 创建新证书身份，成就计数增加 1 |
| 图片脱敏失败 | 公开页无原件，显示失败占位；后台可重试 |
| 续期与撤回并发 | 两条事件均保留；按生效区间归约，最终不冒充有效 |
| 签发机构更名 | 当前名称更新，旧名称和更名时间保留，身份不变 |
| 验证链接 404/超时 | 标记链接失效或来源陈旧，不自动撤销 |
| 签发方记录撤销 | 按撤销事件变更状态并传播；追溯撤销重算历史区间 |
| 上海时间午夜到期 | 使用签发方时区的精确时刻，边界读取正确 |
| 冻结简历遇到撤销 | 冻结快照不变；候选简历和当前技能证据移除 |
| 服务器 NTP 回拨 | 任务重新调度，审计时钟修正，必要时重建投影 |
| 页面折叠排序 | 能展开事件链；只有事实排序，无含金量评分 |

## 12. 当前仓库中的静态演示

`certificates.html`、`css/certificates.css` 和 `js/certificates.js` 是访客墙静态交互原型，使用内置演示数据展示状态、筛选、排序、事件链和失败占位。它不包含管理 API、私密原件存储或真实 OCR；生产实现必须接入后端、对象存储和数据库迁移。
